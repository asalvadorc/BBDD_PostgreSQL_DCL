2.2 PRÁCTICA TCL para Alumnos ASIX

🎯 Objetivo

Aprender a:

  • Utilizar BEGIN / START TRANSACTION
  • Aplicar COMMIT
  • Aplicar ROLLBACK
  • Usar SAVEPOINT
  • Entender la importancia de la atomicidad en bases de datos
  • Relacionar TCL con DCL (roles y permisos)

🗂️ Contexto

Trabajaremos con la base de datos tienda ya creada, con su esquema app, tablas, roles y usuarios.

Cuando se realiza una venta, deben ejecutarse varias acciones:

  1. Registrar la venta
  2. Actualizar el stock del producto

⚠️ Todo esto debe hacerse como una única unidad lógica.

📊 Insertar datos iniciales

Si es necesario:

  • Inserta al menos 2 productos con stock suficiente
  • Inserta alguna venta de prueba

1. Sin Transacción (Para ver el problema)

  • Simular una venta SIN transacción:

    • Inserta una venta de 2 unidades del producto con id = 1
    • Actualiza el stock correspondiente
    • Simula un fallo en mitad del proceso
    • Intenta continuar con otra operación

  • Consultar el estado en el que han quedado las tablas.

📌 Pregunta:
¿Es consistente la base de datos? Razona la respuesta.

2. Uso de BEGIN + COMMIT

  • Repite las operaciones anteriores, pero:

    • Encapsula todas las operaciones en una transacción
    • Finaliza correctamente con COMMIT

  • Consultar el estado en el que han quedado las tablas.

📌 Pregunta:
¿Se han aplicado correctamente todos los cambios? Explica por qué.

3. Uso de ROLLBACK

  • Repite las operaciones anteriores, pero:

    • Ejecuta ROLLBACK antes de finalizar

  • Consultar el estado en el que han quedado las tablas.

📌 Pregunta:
¿Se ha realizado alguna modificación?

4. Uso de SAVEPOINT

  • Repite las operaciones anteriores, pero:

    • Introduce un SAVEPOINT antes de cada operación importante
    • Realiza una operación errónea
    • Revierte parcialmente usando ROLLBACK TO SAVEPOINT
    • Finaliza la transacción

  • Consultar el estado en el que han quedado las tablas.

📌 Pregunta:
¿Qué cambios se han guardado?

5. TCL + PERMISOS

  • Conéctate con el usuario user_tpvs y:

    • Inicia una transacción
    • Intenta modificar el stock de productos
    • Finaliza la transacción

📌 Pregunta:
¿Se permite la operación? Explica qué ocurre y por qué.

6. Reflexión

Responder:

  1. ¿Qué ventaja tienen las transacciones?
  2. ¿Qué ocurriría en un sistema real sin ellas?
  3. ¿Qué diferencia hay entre ROLLBACK y ROLLBACK TO SAVEPOINT?
  4. ¿En qué situaciones reales usarías SAVEPOINT?

RETO FINAL

Crear una transacción que:

  • Venda 2 productos diferentes a la vez
  • Actualice correctamente el stock de ambos
  • Si falla una operación, no se debe registrar ninguna venta
